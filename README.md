## :dart: O guia para alavancar a sua carreira

> MariaDB é o banco de dados relacional open source criado em 2009 pelos fundadores originais do MySQL, mantido pela MariaDB Foundation e usado por gigantes como Wikipedia, Google Cloud, Red Hat e a maioria das distribuições Linux como banco padrão. É praticamente compatível com MySQL na sintaxe SQL, mas evoluiu com recursos próprios — engine de armazenamento Aria, replicação síncrona com Galera Cluster, ColumnStore para analytics, tipos de dados vetoriais para IA e um proxy de banco (MaxScale) para alta disponibilidade. Este guia reúne documentação oficial, cursos, livros, ferramentas de administração, comunidades e um capítulo dedicado a usar IA na prática com MariaDB — tudo verificado, para quem já conhece SQL e quer dominar este banco de dados usado em produção no mundo todo.

## 🤖 IA na prática

MariaDB deixou de ser "só" um banco relacional: desde a versão 11.7/11.8 ele tem tipo de dado **vetorial** nativo, o que o coloca dentro do fluxo de trabalho de IA generativa — não só como fonte de dados, mas como peça de infraestrutura de IA.

**Buscas semânticas e RAG direto no banco**
- [MariaDB Vector](https://mariadb.com/kb/en/mariadb-vector/) — Documentação oficial do tipo `VECTOR`: armazene embeddings (de modelos como os da OpenAI ou Anthropic) direto nas tabelas.
- [VEC_DISTANCE — funções de distância vetorial](https://mariadb.com/kb/en/vec_distance/) — Funções para calcular similaridade entre vetores via SQL puro, a base para montar uma busca semântica (RAG) sem precisar de um banco vetorial separado.
- Na prática: para uma aplicação de RAG pequena/média, dá para guardar os embeddings dos seus documentos numa coluna `VECTOR` e fazer a busca por similaridade com `VEC_DISTANCE` na mesma consulta que já traz os outros dados relacionais — sem duplicar a informação em um Pinecone ou Weaviate à parte.

**Conectando agentes de IA ao seu banco**
- [MariaDB MCP Server](https://mariadb.com/kb/en/mariadb-mcp-server/) — Servidor oficial do protocolo MCP (Model Context Protocol) para MariaDB: permite que assistentes como Claude conversem diretamente com o seu banco (schema, consultas, dados) de forma controlada.
- [Model Context Protocol — servidores oficiais](https://github.com/modelcontextprotocol/servers) — Repositório com implementações de referência do MCP, o padrão aberto que conecta LLMs a ferramentas e bancos de dados.
- [mysql_mcp_server](https://github.com/designcomputer/mysql_mcp_server) — Servidor MCP da comunidade compatível com MySQL/MariaDB, útil para expor um banco a um agente de IA em desenvolvimento local.

**Para trabalhar no dia a dia**
- Use [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com/) ou [Claude Code](https://code.claude.com/docs/en/overview) para: gerar `CREATE TABLE` e migrações a partir de uma descrição em português, escrever consultas complexas com `JOIN`/window functions, revisar um plano de `EXPLAIN` e sugerir índices.
- Peça para a IA **explicar um `EXPLAIN`** linha a linha antes de aceitar qualquer sugestão de índice — otimização de banco tem efeito colateral real em produção.
- Depois de qualquer sugestão de schema ou query gerada por IA, rode em um ambiente de teste com `EXPLAIN ANALYZE` antes de aplicar em produção.

**Limites e boas práticas**
- IA generalista confunde sintaxe do **MySQL** com a do **MariaDB** com frequência (ex.: `SEQUENCE`, `JSON` nativo, `RETURNING`) — sempre confira na [página oficial de compatibilidade](https://mariadb.com/kb/en/mariadb-vs-mysql-compatibility/).
- Nunca cole dados de produção, credenciais ou dumps de clientes em uma ferramenta de IA sem revisar a política de privacidade da sua empresa.
- IA erra sobre nomes de flags de configuração (`my.cnf`) e defaults de versão — confirme sempre na Knowledge Base oficial antes de aplicar em produção.
